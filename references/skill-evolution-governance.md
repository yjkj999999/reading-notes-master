# 技能版本治理 SOP · Skill Evolution Governance

> reading-notes-master **v2.14** · 方法论底座：麦肯锡百年知识库（MECE / 金字塔原理 /
> 假设驱动 / Issue Tree）× GCCEO 全球 CEO 能力进化体系（Self-Improving Agent /
> 四维质量 / 持续进化节奏）。覆盖 MECE 的 **E 版本治理** 层。
>
> 本文件所有数字均为 2026-11-09/10 真实交付实测，**非示例数据**。

## §1 为什么需要一层「治理」

**结论先行**：v2.13 定义契约后，连续五轮实战产生了 20+ 条踩坑经验，但它们散落在
工作日志与项目脚本里，下一个项目仍会重踩。v2.14 的核心不是又加一个功能，而是把
「**实战 → 铁律 → 脚本 → 门禁 → 技能版本**」变成可重复的制度。

| 无治理 | 有治理（v2.14） |
|---|---|
| 经验留在日志，下次重新试错 | 每个项目至少回哺 1 条铁律 + 1 个可复用脚本 + 1 个门禁指标 |
| 版本升级靠堆章节 | 五层 MECE 拆解，互斥且完全穷尽 |
| 指标变好变坏凭感觉 | 同一把尺量三次，数字可横向比较 |
| 报告口径不一致被误读 | 指标口径说明写进 JSON `note` |

## §2 麦肯锡方法论：怎么把经验拆干净

### 2.1 金字塔原理（输出规范）

任何升级说明、交付答复一律 **结论先行 → 依据 → 风险 → 下一步动作**：
第一段给判断与关键数字（如「PASS / 0.0，文字槽 8→530」），不为方法论铺垫；
多方案、问题-根因-修复、指标对标一律表格化；涉及不确定处明确写「缺 X 数据，假设为 Y」。

### 2.2 MECE 五层拆解（本次 v2.14 的实际用法）

| 层 | 边界（互斥判据） | 穷尽性检查 |
|---|---|---|
| A 渲染几何 | 「像素/文字框怎么落位」 | 覆盖所有写入动作 |
| B 内容工程 | 「写什么内容」 | 覆盖内容来源、切分、分配、审计 |
| C 资产构图 | 「用什么图、图够不够」 | 覆盖资产来源、选页、构图量化 |
| D 验收治理 | 「怎么证明合格、怎么固化」 | 覆盖零偏差 / 细节 / 结构 / 报告 / 归档 |
| E 版本治理 | 「经验如何回哺」 | 本文件 |

**互斥检查**：一条经验只归一层。例如「CJK `insert_textbox` 静默失败」归 A（写入动作），
不归 B；「stats 成功但 PDF 无中文」归 B 的审计环节（§8），因为它验的是内容落位结果。
**穷尽检查**：五层之外若还有经验，说明分层需重画，不硬塞进已有层。

### 2.3 假设驱动 + Issue Tree（真实案例：中文覆盖率低）

不要一上来「多写点中文」。先量化基线（PDF 文本层只有 26/40 页有中文），
再按逻辑树拆三支并逐支证伪：

```
中文覆盖率低
├── 槽位层：候选被过滤？ → 13 页文字槽=0（满版摄影页压图图注）→ 证实
├── 写入层：写了但没落位？ → insert_textbox 负值静默不写 → 证实
└── 内容层：流本身有问题？ → 开头是版权/献词、只覆盖 3.2% → 证实（独立问题）
```

三支各自独立修复，互不掩盖；每支修完重跑全链复测。这正是
「**先体检量化 → 假设根因 → 单点修复 → 全链复测**」，禁止盲调。

### 2.4 零基准思考

升级时先问「如果从零设计这条管线还需要 `apply_redactions` 吗？」——答案是不需要，
于是 v2.14 直接把默认路径换成覆盖式替换，而不是在旧路径上继续打补丁。

## §3 GCCEO：持续进化机制落地

| GCCEO 机制 | 在技能里的具体落地 |
|---|---|
| **Self-Improving Agent**（自动捕获错误与最佳实践） | 每个项目收尾必须产出「1 铁律 + 1 脚本 + 1 门禁指标」，写入工作日志与 SKILL.md 错误处理 |
| **四维质量**：温度 / 深度 / 硬度 / 品质 | 温度＝中文场景贴合（CJK 行高、中文标点、¥/涨红跌绿）；深度＝所有数字可复算；硬度＝脚本 `py_compile` + 真实交付实跑；品质＝frontmatter / README / 索引 / 触发词四处版本一致 |
| **季度增量 / 年度大版本** | v2.x 为实战反哺增量（本次 2.13→2.14）；累计多个增量后发 v3.0 重构 |
| **Multi-Agent Orchestration** | 本次四技能协同：主技能（升级对象）+ 麦肯锡（结构）+ GCCEO（治理）+ IMA（归档），各司其职不重叠 |
| **AAR / 复盘机制** | 每轮优化后追加工作日志，记录「问题-根因-修复-实测值」四列，不止记结果 |

> CFO 系统 SOP 对齐：需求定性 → 技能强制加载 → 数据取数 → 多域会审 → 产出交付。
> 本次四技能全部先加载再动笔，未凭通用知识作答。

## §4 六步反哺闭环（每个项目收尾必走）

| 步 | 动作 | 产出物 | 本次 v2.14 实例 |
|---|---|---|---|
| 1 **检测** | 程序化体检，量化基线 | `细节体检.json` 首版 | 色块 15.1%、低对比 13.7%、断章 7.1%、覆盖 3.2% |
| 2 **根因** | Issue Tree 拆支、逐支证伪 | 诊断记录 | 量化色 / 二值阈值 / 硬切 / 单游标 |
| 3 **修复** | 单点改动，改完立即重跑全链 | 新 PDF/PPTX | 精确中位色、WCAG 择优、语义片段、全书等分 |
| 4 **固化** | 铁律写手册、能力写脚本、阈值写门禁 | 3 手册 + 2 脚本 + 1 模板 | `exact-content-engineering.md` 等 |
| 5 **归档** | IMA 精确字节五步 + 工作日志 | 知识库条目 + `.workbuddy/memory/` | 双格式 REPLACE 归档 |
| 6 **交付** | 结论先行的前后对照表 + 文件 | `present_files` | 8 项指标对照 |

**闭环判据**：第 4 步缺失即视为「只做了项目，没升级技能」——这正是本次用户
「全面升级 SKILL」要解决的问题。

## §5 同一把尺量三次

v2.11 提出「量两次」（语料采集 ↔ 生成验收）。v2.14 扩展为**量三次**：

| 次 | 工具 | 量什么 | 同一把尺的含义 |
|---|---|---|---|
| ① 语料采集 | `magcorpus/analyze_mags.py` | 参照刊图像覆盖率 / 暗像素 / 字体 DNA | 同样的像素统计口径 |
| ② 生成验收 | `journal_4k_check.py` / `verify()` | 产物四门 / 槽位外零偏差 | 同参数、同 matrix、同 pad |
| ③ 细节复检 | `detail_audit.py` | 槽位内的中文 / 语义 / 对比度 / 色偏 / 4K | 复用 ①② 的渲染与统计口径 |

三次同源同参数，数字可横向比较；**不以人工目检替代**（本环境 `ViewImage` 不可用时，
一律用 fitz / PIL / numpy 程序化验证）。

## §6 版本发布检查表

发布 v2.x 前逐项打勾，任何一项不过不发版：

- [ ] `SKILL.md` frontmatter `description` 首行版本号、`metadata.version`、正文 H1 三处一致
- [ ] `README.md` 版本徽章、Features 新条目、Changelog 新段、Usage 工作流、Structure 文件树五处一致
- [ ] 新增 `references/` 手册全部存在且被「参考文件索引」表格登记
- [ ] 新增 `scripts/` 全部 `py_compile` 通过；带 `--self-test` 的必须实跑通过
- [ ] 新增脚本对**至少一个真实交付物**实跑，输出 `PASS` 且数字与项目自算一致
- [ ] 质量核对清单补新条目；错误处理补对应坑；触发词补新词
- [ ] 所有引用路径在技能目录下可解析（无悬空链接）
- [ ] 指标口径说明写入报告 `note`（避免 `punctuation_closed_pct` 类误读）
- [ ] 工作日志追加；IMA 归档完成；`dist/` 生成对应版本 zip（可选，仅本地分发）

> **zip 不是 IMA 可上传类型**：content_type 对照表无 zip，离线分发用 zip，
> 知识库归档用 md / pdf / pptx。

## §7 指标口径治理（最容易被误读的一环）

| 指标 | 正确口径 | 常见误读 |
|---|---|---|
| `stats["text"]` | 只统计 `insert_textbox` **成功**数 | 当成「PDF 里有中文的槽数」 |
| `pages_with_cn` | PDF 文本层 CJK 正则实测 | 用构建 stats 推算 |
| `semantic_char_pct` | 来自完整语义短语的字符 / 总字符 | 与「标点收尾比例」混用 |
| `punctuation_closed_pct` | 只量槽位边界是否恰落标点 | 当成语义连续性（尾差补足后必然下降） |
| `eliminated_color_block_pct` | **旧量化算法会产生色块的槽位占比**（优化前基准） | 当成当前产物的色块率 |
| `untouched_pages_identical` | 40 页全改动时检查对象为 0，须注明 | 当成「已验证 40 页」 |

**规则**：口径说明必须写进 `细节体检.json` 的 `note` 与交付说明，数字才可被第三方复算。

## §8 下次升级模板（可直接复制）

```
1. 检测：跑 detail_audit.py 出基线 → 列出未达标门与数字
2. 定性：这条经验归 A/B/C/D/E 哪一层？是否已有条目覆盖？（MECE）
3. 根因：Issue Tree 拆 2–3 支，逐支证伪，记录被排除的支
4. 修复：单点改动 → 重跑全链 → 前后数字对照表
5. 固化：
   - 铁律 → SKILL.md「错误处理」+ 对应 references 手册踩坑表
   - 能力 → scripts/ 可独立运行脚本（含 --self-test）
   - 阈值 → detail_audit.py 八门之一或新增门
6. 发布：按 §6 检查表逐项打勾，版本号 +0.1，四处同步
7. 归档：IMA REPLACE + 工作日志 + 前后对照交付
```
